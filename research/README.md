# 新协议逆向研究（2026-09）

## 结论

2026-07 起通达信服务端对 pytdx 系旧帧（`0c 02` 系）**按功能族断供行情数据**：
TCP 可连、目录/财务类接口（security_count / security_list / finance_info）照常
应答，但实时快照、K 线、分时、除权对旧帧一律静默返回空。官方金融终端改用
本目录逆向出的**新帧格式**（详见 `python/tdxrs/v2_client.py` 模块 docstring）：

- 无握手密钥、无加密：裸 TCP + 正确帧格式即返回数据；
- 登录帧（80B）为静态字节串，可跨连接原样重放；
- 响应帧头 16B：`b1 cb 74 00 | u16 方法回显 | 8B | u16 载荷长 | u16 载荷长回显`；
- 日K记录 36B：`[u32 日期][f32 保留][f32 开][f32 高][f32 低][f32 收]
  [f32 成交额(元)][u32 成交量(股)][f32 流通股本(万股)]`，载荷尾部 120B 为 GBK 名称。

验证：600519 日K 700 根与已知行情逐字段一致（2026-09-11 收 1275.16），
count/category 参数可控，quote/minute/snapshot 均有数据。

## 文件

- `../python/tdxrs/v2_client.py` — 纯 Python 客户端（成品，零依赖）
- `record_proxy.py` / `record_httpproxy.py` — TCP / HTTP CONNECT 录制代理
  （后者实测无效：Mac 版通讯设置的 HTTP 代理不覆盖行情 socket）
- `parse_pcap.py` / `parse_handshake.py` — pcap 帧提取器
- `replay_sequence.py` / `full_sequence_test.py` — 重放验证脚本
- `decode_bars.py` — 日K记录布局解码器
- `*.pcap` / `bars_*.bin` / `*.log` / `captures*/` — 抓包与中间产物（不入库）

## 关键帧（抓包原文，代码占位 `C0DE00`）

| 功能 | 帧长 | 代码@ | 市场@ | 备注 |
|---|---|---|---|---|
| 登录 `00 03` | 80 | — | — | 静态，可重放 |
| 实时快照 `00 05` | 58 | 36 | 34 | 无状态，无需登录 |
| 分时 `00 07` | 50 | 14 | 12 | 需登录 |
| 日K `00 0a` | 58 | 14 | 12 | 需登录；类别 u16@36、条数 u16@44 |
| 市场快照 `00 0d` | 55 | — | — | 无状态 |

## 排障记录（后人少走弯路）

1. Mac 版「通讯设置」主站下拉为固定列表，**无法填自定义 IP**；
2. Mac 版「使用 HTTP 代理」对行情族 socket **无效**（重启进程验证）；
3. 帧边界要靠 TCP 流重组+前缀定位，直接取单包 payload 会混入相邻帧字节；
4. 服务端对格式正确但字段被写坏的帧**静默返回空回声**，不报错——
   偏移动一个字节就是"看起来连上了但没数据"。
